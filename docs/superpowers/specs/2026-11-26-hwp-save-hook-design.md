# 저장 동작과 적용 범위

한글 HWP 저장 런처는 한글 2022 교육기관용 `12.0.0.4645` x86에서 HWP5 저장을 유지합니다. **HWP 저장 유지** 토글은 Windows 사용자별로 저장합니다. ON으로 실행하면 런처가 시작한 한글 프로세스에서 일반 저장과 [다른 이름으로 저장]에 적용됩니다. OFF로 실행하거나 한글을 직접 실행하면 한글 기본 동작으로 시작합니다.

## 지원 조건

| 항목 | 값 |
|---|---|
| GUI | Windows x64, .NET Framework 4.8 이상 WPF |
| 한글 | 검증: 한컴오피스 2022 교육기관용 `12.0.0.4645` x86. 실험: 저장 형식 변환 메서드 구조가 같은 다른 x86 .NET 빌드([버전별 호환성](../../VERSION-COMPATIBILITY.md)) |
| 대상 CLR | .NET Framework CLR v4, `COR_*` 프로파일러 환경변수 |

런처는 App Paths, COM 등록, 문서 연결, 사용자별·시스템 설치 정보와 기본 설치 위치에서 `Hwp.exe`를 찾습니다. 검증된 SHA-256이 일치하는 후보를 우선합니다. 직접 선택한 경로는 `%LOCALAPPDATA%\HwpSaveHook\hwp-path.txt`에 저장합니다. 해당 경로가 유효하지 않으면 자동 탐지합니다. GUI에서 ON을 선택했을 때 검증된 빌드와 프로파일러 DLL이 있어야 **한글 열기**를 사용할 수 있습니다. 같은 Windows 세션에 한글이 이미 열려 있거나 다른 런처가 시작하는 중이면 시작을 중단합니다. 사용자가 저장하고 한글을 닫은 뒤 다시 시도합니다.

더블클릭·바로가기(`--open`)는 한글이 이미 열려 있어도 프로파일러를 붙여 실행합니다. 한글은 두 번째 프로세스의 문서를 기존 창으로 넘기므로, 그 창이 프로파일러 없이 시작됐다면(시작 메뉴, 작업 표시줄, 감싸지 않은 다른 형식의 문서) 저장이 HWPX로 바뀝니다. 런처는 실행 중인 `Hwp.exe`의 모듈 목록으로 이를 판별해 문서를 넘기기 전에 경고합니다. 같은 이유로 더블클릭 연동은 한글이 여는 문서 형식 전체의 한글 ProgId를 감쌉니다. ON인데 빌드가 바뀌어 적용할 수 없으면 일반 모드로 열기 전에 묻습니다.

## 실행 흐름

1. GUI가 `%LOCALAPPDATA%\HwpSaveHook\save-mode.txt`를 읽습니다. 처음 실행하면 ON입니다.
2. 사용자 선택에 맞춰 실행 계획을 만듭니다. 실행 직전에 파일을 다시 검사합니다.
3. ON이면 x86 프로파일러 경로와 CLSID를 자식 한글 프로세스에 전달합니다. OFF이면 자식 환경의 CLR 프로파일러 변수를 비웁니다.
4. 프로파일러는 `Hwp.HwpFrame::ConvertToHwpxPath`를 이름과 시그니처로 찾습니다. verified 모드는 MVID·토큰이 검증 목록과, compatible 모드는 런처가 넘긴 토큰과 일치할 때만 해당 프로세스에서 저장 형식 변환을 건너뛰도록 적용합니다.

일부 상황에서는 저장이 한글의 원래 동작을 따를 수 있습니다.

## 구현 위치

- `private/save-hook/gui/`는 토글, 설치 상태, 실행 버튼과 로그를 표시합니다.
- `private/save-hook/core/`는 설치 탐지, 해시 게이트와 자식 실행을 구현합니다. CLI와 GUI가 공유합니다.
- `private/save-hook/profiler/`는 CLR 프로파일러입니다. 네이티브 DLL은 실행 파일 옆 `profiler/`에 둡니다.
- [tools/inspect_format.py](../../../tools/inspect_format.py)는 저장 결과의 형식을 읽기 전용으로 검사합니다.

본인 PC에서 로컬로 사용합니다. 설치된 한글 실행 파일과 디지털 서명은 런처 실행 전후 동일합니다.
