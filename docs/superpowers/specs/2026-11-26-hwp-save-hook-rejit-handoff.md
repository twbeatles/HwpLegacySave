# 검증 기록

## 저장 호환성

한글 2022 교육기관용 `12.0.0.4645` x86의 실제 설치에서 확인했습니다.

| 시험 | 결과 |
|---|---|
| 빈 문서에서 [다른 이름으로 저장] → HWP | 첫 저장부터 HWP5 `5.1.1.0`, `check-save`의 `expected-output` |
| 굵은 글씨, 표, 이미지, 각주가 포함된 문서 → HWP | 2쪽 재개방, 본문과 컨트롤 일치, 비교한 두 쪽의 픽셀 차이 0 |
| 기존 HWP 편집 → 일반 저장 | ON 실행에서 같은 HWP 파일에 편집 내용 기록. 직접 실행에서는 별도 HWPX가 생성되며 기존 HWP는 유지 |
| 런처 없이 직접 실행 → 빈 문서를 HWP로 저장 요청 | HWPX 전환 안내와 실제 HWPX 확인 |
| 실행 파일 무결성 | 시험 전후 SHA-256 일치, Authenticode `Valid` |
| 이름만 같은 다른 실행 파일 | 불일치 기록 후 적용 없이 종료 |

서식 시험에서 HWP5 기준본과 실제 저장본의 본문, `DocInfo`, 이미지, 미리보기 스트림이 바이트 단위로 일치했습니다. CFB 요약 정보 스트림은 차이가 있었습니다.

이 표는 당시 실행 결과를 요약한 것입니다. 새 실행의 ReJIT 요청과 컴파일 결과는 런처의 **실행 로그 열기**에서 확인할 수 있습니다.

## 런처 UI

2026-11-26 게시본에서 ON과 OFF를 각각 선택하고 앱을 재시작해 설정 복원을 확인했습니다. OFF 상태에서 한글이 일반 실행됐고 한글이 열려 있는 동안 두 번째 실행은 차단됐습니다. ON 상태에서 실행한 한글에서 빈 문서를 저장하자 `check-save`가 HWP5 `5.1.1.0`과 `expected-output`을 반환했습니다. 같은 실행의 프로파일러 로그에서 ReJIT 컴파일 성공을 확인했습니다.

초기 자체 포함 빌드의 실행 파일은 약 133 MiB였습니다. Windows의 .NET Framework 4.8을 사용하는 경량 게시본에서 설치 경로 자동 선택, 직접 지정 경로의 재시작 후 복원, **다시 찾기**로 자동 선택 복귀를 확인했습니다. 자동 선택한 한글에서 저장한 문서는 HWP5 `5.1.1.0`이었고 ReJIT 컴파일 결과는 `0x00000000`이었습니다.

실행 파일은 40,448바이트, 설정 파일은 174바이트, x86 프로파일러는 150,528바이트였습니다. 로컬 x86 프로파일러, x64 GUI, CLI 빌드와 런처 테스트 24개가 통과했습니다. 테스트에는 사용자 지정 설치 폴더의 후보 탐색과 해시 우선 선택이 포함됩니다.

## 반복 검증

- `Build-Local.ps1`로 네이티브 프로파일러와 GUI·CLI를 빌드하고 런처 테스트를 실행합니다.
- GUI를 두 번 실행해 ON/OFF 선택이 재시작 후에도 유지되는지 확인합니다. 같은 Windows 세션에 한글이 이미 열려 있을 때 두 번째 한글 실행이 차단되는지 확인합니다.
- 한글을 닫고 ON으로 실행합니다. **실행 로그 열기**에서 `RequestReJIT` 성공을 확인합니다.
- 빈 폴더에 문서를 HWP로 저장하고 한글에서 닫습니다. Python 3과 `olefile`이 있는 환경에서 [형식 검사 도구](../../../tools/inspect_format.py)를 실행합니다.

```powershell
python -m pip install olefile
python tools/inspect_format.py "C:\test\sample.hwp"
```

`hwp5_candidate`와 `structuralCheck: true`는 복합 파일 안의 HWP 헤더, 버전, `DocInfo`를 확인했다는 뜻입니다. 문서 내용과 배치를 비교하려면 실제 한글에서 다시 엽니다. 일반 동작을 비교하려면 한글을 닫고 OFF로 바꾼 뒤 별도 폴더에서 같은 저장을 시도합니다.
